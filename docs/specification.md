# 地元擁護反論デバイス 仕様書

会話中の「地元に関する誤った認識やネガティブなイメージ」に該当する発言を検知し、インターネット検索による情報源を伴う反論を構築して、音声として発話するデバイス。

## 1. スコープ

設計対象はフロントエンドおよびバックエンド。ラズベリーパイのハードウェア制御(サーボモータ駆動、効果音再生機構)の実装は射程外とし、バックエンドからハードウェア制御部への制御指示のインタフェースのみを定義する。

## 2. 構成

本番環境はスマートフォンとラズベリーパイの 2 台で構成し、PC は含まない。

| 要素 | 役割 |
|---|---|
| スマートフォン(フロントエンド) | マイク入力の受付、バックエンドへの音声ストリーミング送信、反論音声のスピーカ出力 |
| ラズベリーパイ: バックエンド | 認識セッション管理、会話履歴バッファ、一次フィルタ、LLM リクエストの組み立て・発行、音声合成の依頼、スマートフォンおよびハードウェア制御部への送出 |
| ラズベリーパイ: ハードウェア制御部 | 効果音(「ブッブー」)の再生、サーボモータ等の視覚要素の駆動(実装は射程外) |

## 3. 外部サービス

| 用途 | サービス |
|---|---|
| ストリーミング音声認識 | OpenAI Realtime API(文字起こし) |
| 判定・調査・反論構築 | Claude(Anthropic API)+ Web 検索ツール |
| 音声合成 | OpenAI Text-to-Speech |

## 4. 文字起こしの経路

```
フロントエンド → バックエンド → 文字起こしサービス → バックエンド
```

バックエンドが認識セッションを管理し、音声を中継して暫定・確定結果を受領する。認証情報と接続の再確立処理はバックエンドに置く。

## 5. 処理の流れ

**往路**

1. スマートフォンがマイク入力を受け付け、バックエンドへ音声をストリーミング送信する
2. バックエンドが OpenAI の音声認識へ音声を中継する。文字起こしはトリガの有無にかかわらず常時行う
3. 確定結果を会話履歴バッファに時系列で蓄積する
4. 確定結果ごとに一次フィルタで LLM への発火を判定する
5. 発火時、Claude API へリクエストを発行する。反論の要否の精密な判定は LLM が担う

**復路**

6. Claude の反論テキストを OpenAI の音声合成で音声に変換する
7. 合成音声をスマートフォンへ送出し、スピーカから再生する
8. 併せてハードウェア制御部へ制御指示を送る。順序は効果音 → 視覚的演出 → 反論の発話

## 6. 会話履歴バッファ

- 固定長のリングバッファ。各要素は `{タイムスタンプ, テキスト}`
- 確定結果の到着ごとに追記し、発火とは独立に常時更新する

## 7. 一次フィルタ

- 文字起こしの確定結果の単位で判定する(暫定結果には適用しない)
- 地元関連語彙(地名、名産、施設名、方言等)の辞書マッチング。表記揺れは正規表現または形態素解析で正規化する
- 取りこぼし最小の緩い運用とし、絞り込みは LLM に委ねる

## 8. LLM リクエスト制御(上書き方式)

- トリガが立つたびにリクエストを発行する
- 連鎖の起点となるリクエストは、トリガ発言+バッファからの直近履歴を含む
- 応答が届く前に次のトリガが立った場合、新リクエストには直前リクエストの文脈+新規分をマージして含め、旧リクエストの応答は棄却する
- トリガが立たなくなるまで繰り返し、最新世代の応答のみを発話する
- 世代番号(単調増加)で棄却を制御し、旧世代のストリーミング接続は打ち切る
- 連鎖の終了(応答の発話)で文脈を閉じ、次のトリガから新しい連鎖を始める
- 世代数・経過時間に上限を設け、到達時はその時点の最新応答を発話する

**リクエストの内容**

- システム指示: デバイスの役割、反論不要と判断した場合は応答しない旨、出力形式
- 会話履歴(トリガ発言をマーカーで明示)
- Web 検索ツールの利用許可

## 9. 機器間通信

| 区間 | 内容 |
|---|---|
| スマートフォン ⇔ バックエンド | WebSocket 等の常時接続。往路: 音声ストリーム、復路: 合成音声 |
| バックエンド ⇔ 音声認識(OpenAI) | ストリーミング文字起こしセッション(送信と結果受領が同一接続)。API キー認証 |
| バックエンド ⇔ Claude API | リクエスト発行・ストリーミング応答受信。世代管理による棄却 |
| バックエンド ⇔ 音声合成(OpenAI) | テキスト送信・合成音声の受領。API キー認証 |
| バックエンド ⇔ ハードウェア制御部 | 同一ラズベリーパイ内の連携。効果音再生・サーボ動作の制御信号のみ(音声データは送らない) |

## 10. 運用上の前提(実装対象外)

本節は運用者が各サービスのアカウント設定で担保する事項であり、本プロジェクトのコードの責務ではない。コードでの実装は不要。

- 外部サービス(Anthropic、OpenAI)はクレジット事前購入方式で利用し、自動チャージは無効とする
- これにより、無制限の従量課金となる構成を避ける
